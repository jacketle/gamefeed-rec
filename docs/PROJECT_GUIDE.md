# GameFeed-Rec技术讲解

项目围绕两个问题展开：候选从哪里来，以及已有历史怎样帮助判断用户会不会观看达标。Pure把召回、排序和页面串成完整流程；1K使用连续日志，进一步检验历史特征的效果。

当前结果：Pure的配额候选＋RRF排序达到25.32%测试Recall@100；1K的B0＋显式历史匹配达到0.69377平均测试GAUC，比B0提高0.300个百分点。详见[最新报告](../reports/optimization_v2/summary.md)。

## 1. 两条流程怎样连接

**Pure：日志 → 按日历史 → 多路召回 → 固定100候选 → 排序对照 → 本地演示。**

先按时间分训练、开发和测试，再为每个用户日期构造前一天结束前的历史。热门、ItemCF、BGE和双塔提供对照。最终选用热门保留10条、ItemCF补齐100条的候选组成方式，再按RRF名次分数排序。页面默认展示这一顺序，行为预测模型保留为重排对照。

**1K：完整用户日志 → 逐事件历史 → B0/B1/B2 → 作者与显式匹配对照 → 配对种子验证。**

历史只包含严格早于当前请求的常规观看达标事件，同时间戳互不进入历史。B0编码用户、视频、标签、场景及数值特征；B1加入历史均值；B2按候选对历史加权。后续通过作者频次、初始化尺度与三个匹配特征，定位此前增加特征却下降的原因。

1K模型是曝光预测实验，Pure页面仍使用Pure候选和模型，两者各有数据切分与评价入口。

## 2. 最值得讲清楚的设计

| 设计 | 实现与原因 |
| --- | --- |
| 时间边界 | Pure按日回放；1K按事件时间构造历史，明确排除同时刻事件。避免当前反馈进入当前特征。 |
| 未训练ID处理 | 未训练视频使用零ID向量并保留已知标签；未训练用户、场景与未见作者有明确回退。 |
| 固定候选评价 | 同一组100条候选比较排序，便于区分召回漏掉了正例，还是排序把正例放得太后。 |
| 公平的特征对照 | 新增特征时保持公共层初始参数一致，新增输入列权重从0开始，训练样本与评价频率一致。 |
| 开发集选停点 | 前两轮每四分之一轮评价，此后每轮评价；连续两轮未改善结束，保存最佳开发GAUC检查点。 |
| 配对复核 | 同样的三个种子训练B0与优胜方案，再对同一批用户计算差值与抽样区间。 |

## 3. 这轮改善具体来自哪里

原先把全部作者ID映射成16维向量，直接拼到B0预测头，开发GAUC下降。第二轮将原因拆开：全量作者、高频作者、高频作者＋小初始化、显式匹配分别对照同一B0。

种子2026的开发GAUC从B0的0.69461，依次得到0.69218、0.69492、0.69659、0.69849。作者出现1次、2–5次、6–20次的分组在全量作者模型中均下降；高频筛选和小初始化改善了作者方案。这个结果说明特征效果依赖样本支持与训练方式。

最终采用三个显式匹配数值：

1. 当前候选作者在有效历史中的占比。
2. 有效历史中是否出现当前候选作者。
3. 与候选至少共享一个已知标签的历史占比。

空历史返回0；缺失作者、未知标签不计为匹配。这些数值直接表达候选与用户已有兴趣的关系，接入原64维隐藏层仅新增 `3 × 64 = 192` 个权重。

同作者匹配覆盖约1.01%的开发曝光，同标签匹配覆盖约67.27%。三种子平均开发GAUC为0.69888，测试为0.69377；测试相对B0提升0.300个百分点，95%用户配对区间[0.220，0.380]。目前验证的是三个特征组合的效果，各列贡献可通过单独消融继续区分。

## 4. 结果如何解释

**曝光AUC提高，不等于召回候选的前10条更好。** 曝光分类评价的是实际展示过的样本；候选重排面对召回生成的候选集合。Pure行为预测模型的AUC可以较高，但重排后的Recall@10下降。因此最终选择依据推荐列表指标，并保留RRF作为演示默认。

**增加历史并不自动获益。** 早期B1、B2的测试GAUC为0.68705、0.68795，低于B0的0.69076。它们保留为历史表示方式的对照；当前优选是B0加显式匹配。用同一框架记录失败方案，使后续改动有明确参照。

**0.300个百分点是绝对差值。** 三个种子的测试GAUC差值都为正；报告对已训练模型进行用户整体配对抽样，保留同一用户多条曝光的关系。既有测试集属于本项目回顾性比较，这组结果用于说明当前数据和模型上的改善。
